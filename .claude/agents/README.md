# エージェントチーム

このリポジトリに常駐する**マーケ2体・デザイン2体**のチームです。
オーナーはマーケティングとデザインの専門家ではないので、**4体の仕事は「実装すること」ではなく
「オーナーが専門知識なしで可否を判断できる提案を出すこと」**に設計されています。

## メンバー

| エージェント | 持ち場 | 答える問い |
| --- | --- | --- |
| `marketing-positioning` | 誰に何を、いくらで | なぜ他のアプリではなくこれを使うのか／なぜ払うのか |
| `marketing-growth` | 客を連れてくる | どう見つけられ、どう選ばれるか（ASO・掲載文・LP・ローンチ・計測） |
| `design-ux` | 迷わず終わらせられるか | 何タップで終わるか／迷う場所／抜けた状態／アクセシビリティ |
| `design-visual` | 見た目と外に出す絵 | デザインシステムの整合／アイコン／スクリーンショット／Figma |

**2体ずつに割ったのは、役割が衝突したときに議論が見えるようにするためです。**
「売れるか」と「使えるか」を1体に持たせると、片方が静かに潰れます。

## 呼び方

```
> marketing-positioning で、競合の me:new と レピモ のストアページとレビューを読んで、
  このアプリが「献立アプリ」として戦うべきか「家族の暮らしの台帳」として戦うべきかを検証して

> design-ux で CalendarScreen のアクセシビリティを見て

> design-visual にアプリアイコンが無い問題を提案にまとめてもらって
```

明示的に名前を出さなくても、話題が合えば自動で選ばれます。
複数体に同じ題材を投げて**意見を戦わせる**のも有効です（例: 価格 × 使いやすさ）。

## 4体が共有しているもの

| ファイル | 役割 |
| --- | --- |
| `docs/product/product-brief.md` | **事実の置き場**。推測で語る前に全員ここを読む。`❓未確定` が下流の依存元 |
| `docs/proposals/README.md` | 提案の出し方・ステータス・制約（同時 draft は1体3件まで） |
| `docs/proposals/TEMPLATE.md` | 提案書の型。**「却下すべきサイン」を必ず書かせる** |

### 全員に共通の禁止事項

- **数字を作らない。** このプロダクトにはユーザー・アナリティクス・ストア指標が1件もありません。
  「CVR が 3% 上がります」は嘘です。出典のある数字だけを、出典つきで
- **`❓未確定` を勝手に決めて下流を積み上げない。** 未確定そのものを埋める提案は歓迎
- **白紙の質問を投げない。** 専門知識がない相手に「どうしますか？」は無効。
  選択肢＋推奨＋理由の形にする
- **好みを基準にしない。** 外部の物差し（WCAG / iOS HIG / ストア要件 / デザインシステムの確定値）か、
  数えられる事実（操作数・トークンから外れた箇所の数）に限る

## 提案の流れ

```
エージェント
  ├─ ① docs/proposals/NNN-slug.md を PR で出す   … 根拠と履歴が git に残る
  └─ ② [draft] 付きの issue を立てる              … 議論の場。要約＋md へのリンク
        ラベル: draft ＋ marketing / design

        ↓ オーナーが読む

  採用 → draft ラベルを外す／md を accepted に
  却下 → issue を close（not planned）／md を rejected にし**理由を1行**
  保留 → md を parked に
```

却下した提案書は**消しません**。「なぜやらなかったか」が次の提案の材料になります。

## ラベル

`draft` / `marketing` / `design` を使います。**リポジトリに無い場合は issue 作成時に自動で作られます**
（色はデフォルト）。見やすくしたいなら手で色を付けてください。

## 将来：定期的に自分から提案を出させる

`docs/proposals/` に溜まった判断と、ブリーフの `❓未確定` の減り方を見ながら、
**定期実行（Routine）で自分から draft を出す**構成にできます。まだ設定していません。

始めるなら、こう頼んでください。

```
> 毎週月曜の朝に marketing-positioning と design-ux を動かして、
  未判断の draft が3件未満なら新しい提案を1件ずつ出す Routine を作って
```

**先に片付けたほうがよいこと**が2つあります。自動化を急ぐと空回りします。

1. **ブリーフの `❓未確定` を1つでも埋める。** 特に「誰の痛みか」。
   これが未定のまま週次で走らせると、一般論の提案が毎週3件積まれて終わります
2. **最初の数件は手で呼んで品質を確かめる。** 提案書の型が期待どおりか、
   `却下すべきサイン` が本当に書けているかを見てから自動化してください
