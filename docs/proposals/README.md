# 提案（draft）

マーケ／デザインのエージェントが出す**提案書**の置き場です。
オーナー（マーケとデザインの専門家ではない）が可否を判断するための書類なので、
形式は `TEMPLATE.md` に厳密に従います。

## 流れ

```
エージェントが提案を作る
  ├─ ① docs/proposals/NNN-slug.md を書く   … 根拠と履歴が git に残る
  └─ ② draft issue を立てる                 … 議論の場。本文は要約＋md へのリンク
        ラベル: draft ＋ marketing / design

           ↓  オーナーが読む

  採用 → issue の draft ラベルを外す。md の status を accepted に
  却下 → issue を close（not planned）。md の status を rejected にし、**理由を1行足す**
  保留 → issue はそのまま。md の status を parked に
```

**却下した提案書は消しません。** 「なぜやらなかったか」が次の提案の材料になります。

## ステータス

| status | 意味 |
| --- | --- |
| `draft` | 提案中。まだ誰も判断していない |
| `accepted` | やる。実装 issue に落ちている |
| `rejected` | やらない。理由が本文末尾にある |
| `parked` | 今はやらない。条件が変われば再検討 |
| `superseded` | 別の提案に置き換わった（置き換え先の id を書く） |

## エージェントへの制約

- **未判断（`draft`）の提案は、1エージェントあたり同時に3件まで。**
  溜まったら新しい提案を作らず、既存の draft を磨くか取り下げてください。
  issue 一覧が推測で埋まるのが一番の害です。
- 番号 `NNN` は既存の最大値＋1。衝突したら振り直す。
- **`docs/product/product-brief.md` の ❓未確定 に依存する提案は、依存を明記する。**
  未確定を勝手に決めて下流を積み上げてはいけません。
  未確定そのものを埋める提案（「これを聞く／これを調べる」）は歓迎します。
- 提案書の中で**オーナーに質問してよい**。ただし「どうしますか？」ではなく
  選択肢と推奨をつけること（専門知識がない人に白紙の質問を投げても答えは返りません）。
